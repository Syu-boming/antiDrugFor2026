## 名詞小辭典

正文的術語第一次出現時會順便解釋；忘了的話查這裡。

| 名詞 | 意思 |
|---|---|
| 關卡 G1–G7 | 製作分成 7 關：G1 劇本、G2a 美術風格、G2 角色母版與試作、G3 聲音、G4 代表鏡頭（全劇品質基準）、G5 各幕、G6 全劇、G7 交付（v1.3 第 4.2 節）。 |
| 驗收包 | 程式自動產生的檢查資料（關鍵畫面、錄影、量測數字）。驗收代理只看這個打分數，看不到製作說明（v1.3 第 4.1 節）。 |
| 嚴重問題／一般問題 | 嚴重問題一票否決，一定要修好（例如違反兒童安全界線、閃爍、八題答案錯）。一般問題修兩輪後可以「記錄放行」（v1.3 第 4.3、4.4 節）。 |
| 帶一般問題放行 | 沒有嚴重問題，但還有小缺點；記下來，先往下一關走。 |
| resolved／partial／not／未驗證 | 重驗代理對舊問題的判定：已解決／部分解決／沒有改（多半是主線裁定不改）／這次沒有證據可判。 |
| 光敏 | 檢查畫面每秒明暗或紅色變化不超過 3 次（安全界線第 9 條）。「細格」＝把畫面切成 32×18 小格逐格檢查。 |
| 孤立單格亮度比 | 換鏡頭那一格，整個畫面突然變亮或變暗的倍數。超過 1.2 倍判不通過。 |
| LUFS／LU | 聲音響度的單位。數字越接近 0 越大聲。「±1 LU」＝各段音量相差不超過約 1 個單位。「對白高出背景 12 LU」＝台詞比配樂、音效大聲約 12 個單位。 |
| dB | 音量或畫質差距的單位。 |
| 配樂避讓（musicDuck） | 有台詞時把配樂自動壓低。musicDuck 是可以單獨指定某一段壓多低的設定（預設 0.56 倍）。 |
| PSOLA | 把配音拉長、縮短或升降音高的後製方法。改太多可能聽起來不自然。 |
| 轉寫模型 | 把配音轉成文字的程式（small、large-v3-turbo 兩種），用來代替耳朵檢查有沒有念錯。 |
| 投影模擬 | 用程式模擬投影機洗白、變灰後的畫面，檢查字和角色還看不看得清楚。 |
| 建置 | 把劇場程式和素材組成可以直接開的檔案（`app/dist/`）。每次改程式都要重新建置。 |
| 資料包 | 建置裡裝圖、聲音、劇情資料的檔案（`data/*.js`，全部約 417 MB）。少一個就可能開不了。 |
| engine-test | 劇場程式的自動測試（按鍵、八題、字幕、缺檔等）。 |
| 冒煙測試（delivery_smoke） | 自動打開交付資料夾裡的兩個版本，檢查和建置逐檔相同、能載入全劇、八題正確、署名卡、零網路請求的程式。 |
| 查核點 | 控制台上 4 個時間檢查點，落後太多就提示壓縮（1 級、2 級）。 |
| 退路 | 原方案修兩輪還不行時的替代做法（v1.3 第 4.4 節）。 |
| Electron 可攜版 | 不用安裝、雙擊 `AntidrugTheater.exe` 就能開的 Windows 版本。 |
| 備援影片 | 劇場程式打不開時用的分幕影片，用一般播放器播放，沒有互動。 |
| PSNR | 影片畫質和原始畫面有多接近的分數（dB）。約 40 dB 以上肉眼通常看不出差別。 |
| all_ok | 備援影片自動檢查的總判定（畫格數、聲音、聲畫同步、逐格對齊等全部通過＝是）。 |
| GitHub、commit、main | GitHub 是放原始碼的網站；commit 是一次存檔紀錄，用 7 碼代號表示（例如 1c48923）；main 是主要分支（正式的那一條紀錄）。 |
| 強制推送 | 用改寫過的紀錄覆蓋 GitHub 上的舊紀錄。會刪掉舊版本，屬於破壞性操作，所以 Claude Code 的自動安全檢查會擋下來。 |
| gh-pages／線上版 | GitHub 提供的網頁空間，放線上預覽版（https://syu-boming.github.io/antiDrugFor2026/）。 |
| 指紋（sha1） | 從檔案內容算出的一串代號；內容改一個字，代號就不同。用來確認「是不是同一版」。 |
